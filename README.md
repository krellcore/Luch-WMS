# Луч — Система управления складом

**«Склад на просвет»**

Версия **1.0.1**

---

Луч — это WMS-система (Warehouse Management System) с адресным
хранением, заданиями и тонкими клиентами. Вся бизнес-логика хранится
на сервере. Клиенты (ПК-клиент управления, ПК-терминал, Android-ТСД)
не знают предметной области — они рендерят дерево компонентов (view/mgmt-view),
которое им присылает сервер.

---

## Состав

| Компонент | Расположение | Описание |
|---|---|---|
| Ядро | `main.py` + `utils/` | Управление складами |
| HTTP-сервер | `utils/server.py` | API, протоколы v1.0 |
| Headless-сервер | `utils/wms_server.py` | Без UI, для выделенного ПК |
| Обработчики заданий | `utils/tasks/` | pick, receive (shared с сессией), putaway, inventory |
| Сессии | `utils/sessions/` | Приёмка на ПК (receive) |
| View-протокол (терминалы) | `utils/view_protocol.py` + `view_builder.py` | Для ПК-терминала и ТСД |
| Mgmt-протокол (ПК-клиент) | `utils/mgmt_protocol.py` + `mgmt_pages/` + `mgmt_render.py` | Для ПК-клиента управления |
| Базовый класс ПК-страниц | `utils/mgmt_client_base.py` | MgmtPageBase — тонкий HTTP-клиент, по `PAGE_KEY` запрашивает `/mgmt/page/{key}` |
| Публичный API плагинов | `utils/api_public.py` + `plugin_hooks.py` | Точки расширения |
| Реестр ролей | `utils/roles.py` | Встроенные + от плагинов |
| Загрузчик плагинов | `utils/plugins.py` | Папки + legacy `.py` |
| ПК-клиент управления | `utils/wms.py` | Тонкий mgmt-клиент |
| Статус сервера | `main.py` (ServerStatusWindow) | Окно с метриками сервера |
| ПК-терминал | `client_desktop/` | Тонкий view-клиент |
| Android-клиент | `WMSClient/` | Тонкий view-клиент |
| Плагины | `plugins/` | Папки плагинов |

## Способы запуска

### Сервер + клиент (на одном ПК)

Самый частый вариант. Один ПК: сервер в фоне + клиент управления.
Открывается окно статуса сервера и окно клиента.

```bash
python main.py
```

Выбрать склад → «Сервер + клиент».

Wizard создания задач и все разделы — доступны.

### Только сервер (headless)

Сервер без клиента. Подходит для выделенного ПК — за ним никто
не сидит.

```bash
python main.py
```

Выбрать склад → «Только сервер». Откроется только окно статуса.
Клиенты подключаются по сети.

Или напрямую:

```bash
python utils/wms_server.py warehouses/<name>
```

### Удалённый клиент (с других ПК)

На каждом рабочем ПК:

```bash
python main.py
```

→ «↗ Подключиться к удалённому серверу». Адрес сервера вводится
в диалоге логина.

Или напрямую:

```bash
python utils/wms.py --server http://<ip>:8765
```

В заголовке окна будет название склада, полученное от сервера.

## Окно статуса сервера

Открывается при запуске сервера (любым способом). Показывает:

- 🟢/🔴 состояние сервера, uptime;
- название открытой БД;
- количество подключённых админ-клиентов и рабочих клиентов,
  разбивка по устройствам (pc / android);
- нагрузку: потоки, запросы/сек, за час, за день;
- трафик: принято/отправлено в секунду, за час, за день, всего.

Кнопка «Остановить сервер» — убивает процесс сервера и показывает
лаунчер. Закрытие окна через крестик не останавливает сервер.

## Файловая структура склада

```
warehouses/
└── <name>/
    ├── warehouse.db     база склада
    ├── ui.json          тема и тексты (опционально)
    └── badges/          пропуска сотрудников

```

Резервная копия — скопировать папку склада целиком.

## Установка

### Сервер и ПК-клиент управления

```bash
pip install -r requirements.txt
python main.py
```

### ПК-терминал

```bash
cd client_desktop
pip install -r requirements.txt
python main.py
```

### Android-ТСД

Готовый APK ставится на устройство с Android 7+.
Сборка из исходников — см. `WMSClient/how-to-build.txt`.

**Важно:** собирайте **release** APK, а не debug. Debug-сборка
Compose в разы медленнее и на слабых ТСД (например, Newland
MT-65 Beluga 3) заметно лагает. В `app/build.gradle.kts`
`isMinifyEnabled = true` только для release.

## Ключевые особенности

- **Тонкие клиенты.** Все клиенты (терминалы, ПК-клиент управления)
  рендерят дерево компонентов, не зная предметной области. Вся верстка
  и логика ПК-клиента управления генерируется на сервере (`utils/mgmt_pages/`).
  Клиентские разделы ПК-клиента — экземпляры `MgmtPageBase`
  (`utils/mgmt_client_base.py`), без собственной вёрстки.
- **Приёмка — только через сессию.** Задания типа `receive` через
  `/tasks/next` не выдаются. Приёмка выполняется через
  `sessions/receive.py` на ПК-терминале.
- **Несколько руководителей.** Роли `owner` / `admin` / `operator`.
  Учётные записи создаёт только `owner`.
- **Пароли — только хэши.** В БД хранится SHA-256 хэш пароля.
- **Резервы.** При создании подбора товар резервируется на 120 мин.
  Резерв продлевается до 60 мин на каждом действии клиента.
- **Ручные операции.** В разделе «Просмотр склада» доступны операции
  подбора, размещения и инвентаризации напрямую из карточки ячейки.
- **Safe mode.** `--safe` — запуск без плагинов. Сервер работает,
  mgmt-разделы доступны (включая headless).
- **Статус сервера.** Отдельное окно с метриками (uptime, клиенты,
  нагрузка, трафик).
- **Локализация.** Язык на клиенте, передаётся в каждом запросе.
  Все строки — через `tr()`; `task_plan` хранит ключи, а не готовый
  текст. Языки плагинов лежат в `plugins/<name>/lang/*.json`
  и мержатся с общими под префиксом `plugin.<name>.`.
- **Кэш `ui_config` и `settings`.** Оба клиента (ПК-терминал,
  Android) кэшируют `/ui_config` (тема, экраны, меню, языки, роли)
  и `/settings` (настройки склада) локально. Проверка актуальности —
  **только при подключении к серверу** (старт приложения или скан
  QR). В течение сессии сеть для этих запросов не дёргается.
  Проверка версии через `POST /ui_config/version`.
- **Роли.** Встроенные (`picker`, `receiver`, `putaway`, `inventory`)
  + регистрируемые плагинами через `context.register_role(...)`.
  Реестр отдаётся клиентам в `/ui_config.roles`; роли учитываются в
  `/tasks/next`.
- **Android-сканер.** На ТСД — HID-перехват через
  `MainActivity.dispatchKeyEvent` (без `AndroidView`/`EditText`,
  без фокуса на скрытом поле). На телефоне — встроенное превью
  камеры в окне задания/сессии (снизу, ~240 dp) с кулдауном
  1 секунда; на экранах логина — полноэкранный `CaptureActivity`
  (zxing) с портретной ориентацией.
- **Плагины — папки.** Плагин = папка в `plugins/` с `plugin.json`,
  точкой входа (`plugin.py`), (опционально) `lang/` и доп. файлами.
  Папка грузится как пакет `luch_plugin_<name>`, поэтому внутри
  работают относительные импорты (`from . import helpers`). Старый
  формат (один `.py` файл) поддерживается для совместимости.
- **Плагины: mgmt vs legacy.** Для всех режимов (включая удалённый
  и headless) — `register_mgmt_page` (выполняется на сервере,
  работает без установки плагина на клиенте). Устаревший
  `register_page` (Qt-класс на клиенте) работает **только в
  локальном режиме** («Сервер + клиент» на одном ПК).
- **Плагинные страницы в сайдбаре ПК-клиента.** При активации
  плагин регистрирует mgmt-страницу — она **сразу** появляется
  в сайдбаре (если роль подходит). Деактивация — удаляет.
  В удалённом режиме клиент подтягивает список страниц с
  `/mgmt/pages` при старте и по кнопке «Обновить» в «Плагинах».

## Журнал изменений

### 1.0.1

**Сервер**

- Реестр ролей `utils/roles.py`: встроенные + от плагинов.
  `/ui_config.roles` отдаёт клиентам актуальный список ролей
  (`key`, `title`, `title_key`).
- `context.register_role(key, title_key=, title=, task_types=)` —
  штатный способ добавить роль из плагина. Роль появляется в
  карточке сотрудника, в фильтрах «Сотрудники» и «Уведомления»,
  учитывается в `/tasks/next`.
- `_get_plugin_context(plugin_name)` — для страниц и меню плагина
  возвращает его настоящий `PublicContext` (с `db()`, `tr()`,
  `query()`); fallback `_Ctx` теперь тоже предоставляет тот же
  минимальный API. **Исправлен баг**, из-за которого падал
  `AttributeError: '_Ctx' object has no attribute 'db'` при
  рендере плагинных страниц.
- **Исправлен баг** с кнопками на плагинных mgmt-страницах:
  `_mgmt_page_action` теперь уважает `result["view"]`,
  возвращённый handler'ом (раньше пересобирал страницу через
  builder и терял открытый диалог — «кнопки не работали»).
- `_translate_notification`: если после перевода по `payload.key`
  в сообщении остались `{name}`, они подставляются из
  `payload.params`. Уведомления больше не показывают «{barcode}»
  сырым текстом.
- Отчёты по заданиям разделены по типам:
  - `pick` — артикул/название/ШК/ячейка/ожидалось/принято/статус
    + блок «Отложенные (неизвестные) товары»;
  - `receive` — + статус `extra` («сверх плана»);
  - `putaway` — тара/статус/остаток в таре;
  - `inventory` — из `inventory_reports`: ячейка/артикул/было/стало
    + строка «Тары с неизвестными ШК».
- `pick._not_found_apply`: блок-этаж (`bf_prefix`) берётся из
  адреса ячейки, а не из первых двух символов ШК. Исправлена
  ошибка, из-за которой товар «в блоке» не находился при
  заданном `prefix_cell` и вместо добавления второй ячейки в
  маршрут создавалось новое задание.
- `tasks._create_pick`: `cell = r[0]` вместо `r["cell_barcode"]`
  (курсор без `row_factory` → `TypeError: tuple indices...`).
  `_wizard_create` устанавливает `row_factory = sqlite3.Row`.
- `containers._manual_receive_dialog` — таблица тар с поиском
  вместо выпадающего списка; `containers._manual_receive_apply`
  берёт контейнер из `table_containers_selected`.
- `tasks._add_container_dialog` — колонка «Товаров» (сумма
  `placed_instances`); пустые тары скрыты.
- `tasks._add_cell_dialog` — таблица всех ячеек с поиском вместо
  текстового поля (для wizard инвентаризации).

**Плагины**

- Формат «папка»: `plugin.json`, `plugin.py`, `lang/*.json`,
  доп. файлы. Папка грузится как пакет `luch_plugin_<name>` —
  работают относительные импорты. Legacy `.py`-файлы
  поддерживаются; папка приоритетнее.
- `plugins/<name>/lang/*.json` — свои переводы. Ключи
  оборачиваются в `plugin.<name>.`; в коде плагина
  `context.tr("key")` (автопрефикс) и `context.tr_in(loc, "key")`.
- `context.register_role(...)` — см. выше.
- Добавлен `plugins/_template/` — каркас для нового плагина.
- `plugins/example_printer/` и `plugins/example_hooks/` переведены
  в формат «папка»; `example_hooks` содержит `helpers.py`
  (пример доп. модуля).
- Новый пример `plugins/example_audit/`: mgmt-страница, пункт
  меню ТСД, свой тип задания `audit`, своя роль `audit`, папка
  `lang/` с тремя языками.

**ПК-терминал (`client_desktop/`)**

- Кэш `ui_config` в `config.json.ui_cache[<server>] = {version,
  config}`. Проверка через `POST /ui_config/version` при старте
  и после скана QR. В сессии не перезапрашивается.
- Кэш `/settings` в `config.json.settings_cache[<server>|<login>]`.
  При логине — попытка сети, при неудаче — fallback на кэш.
- `_apply_locales` больше не фильтрует по префиксу `client.`:
  мержит все ключи (плагины и роли тоже видны).
- `LanguageDialog` показывает **все** языки из кэша
  (`available_locales()`), включая `de.json` и любые
  плагинные.

**Android (`WMSClient/`)**

- `Lang.loadFrom` без фильтра `client.` — плагинные переводы и
  `role_*` доходят до клиента. `Lang.t` с null-safe `?:` и
  fallback для `role_*` (`Audit`, `Cell audit`).
- `WmsViewModel.roleLabel(key)` — берёт из `ui_config.roles`
  по `title_key`, fallback на `Lang.t("role_<key>")`.
- `UiConfig.roles` (список `RoleInfo`: `key`, `title`,
  `title_key`) — парсится из `/ui_config`.
- Кэш `/settings`: `wms_settings` SharedPreferences по ключу
  URL сервера; при логине — попытка сети, fallback на кэш.
- Сканер на ТСД: `MainActivity.dispatchKeyEvent`, без
  `AndroidView`/`EditText`/focus-retry (это убирало лаги на
  MT-65).
- Drawer: ширина 240 dp, анимация 120 мс линейная
  (`tween` с `LinearEasing`); `key(stepNo)` вокруг сканера
  убран — `AndroidView` не пересоздаётся на каждом шаге.
- Встроенный сканер камеры (`EmbeddedCameraScanner`) в окне
  задания/сессии на телефоне, кулдаун 1 секунда; полноэкранный
  `CaptureActivity` (zxing) остаётся только на экранах логина.
- `WmsLogo()` — пре-скейл логотипа (`Bitmap.createScaledBitmap`)
  один раз в `remember`.

**Лаунчер (`main.py`)**

- Селектор языка строится из `available_locales()`
  (`utils/i18n.py`), а не из хардкода `ru`/`en`. `de.json`
  (и любой другой `lang/*.json`) появляется в списке после
  перезапуска.
