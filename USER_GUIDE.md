## 1. Что такое Луч

«Луч» — WMS для адресного хранения. Состоит из четырёх
взаимодействующих программ:

1. **Сервер** — хранит БД склада, отвечает на HTTP-запросы.
   При включённом TLS — по HTTPS.
2. **ПК-клиент управления** — окно руководителя: разделы
   «Просмотр склада», «Задания», «Артикулы», «Тары», «Точки
   сброса», «Уведомления», «Настройки», «Сотрудники»,
   «Руководители», «Плагины», «О программе» (+ разделы,
   добавленные плагинами).
3. **ПК-терминал** — тонкий клиент на рабочем ПК: получение
   заданий и выполнение сессии приёмки.
4. **Android-клиент** — тонкий клиент на ТСД или телефоне:
   получение заданий и сканирование.

Вся бизнес-логика на сервере. Клиенты рендерят дерево
компонентов, не зная предметной области.

## 2. Установка

### 2.1. Сервер и ПК-клиент управления

```bash
pip install -r requirements.txt
python main.py
```

В `requirements.txt` входят `PySide6`, `python-barcode`, `Pillow`,
`qrcode[pil]` и **`cryptography`** (нужен для генерации TLS-сертификата
при создании склада).

### 2.2. ПК-терминал

```bash
cd client_desktop
pip install -r requirements.txt
python main.py
```

### 2.3. Android-клиент

См. `WMSClient/how-to-build.txt`. APK ставится на Android 7+.

### 2.4. Данные

`warehouses/<name>/warehouse.db`. При включённом TLS рядом —
папка `tls/` с сертификатом. Резервная копия — вся папка склада
целиком. Программа 1.1.x не поддерживает старые склады
(«нет миграций»).

## 3. Терминология

- **Тара** — физический ящик/лоток, у которого есть штрихкод.
  Статусы: `free`, `accepting`, `placing`, `picking`, `waiting`,
  `closed`, `unknown_scan`.
- **Ячейка** — адрес вида `45-03-07-B2`, у неё тоже есть ШК.
- **Грузоместо** — тара или партия товара, которую принимают.
- **Сессия** — долгоживущий процесс (например, приёмка).
- **Задание** — конкретная работа (`pick`, `putaway`, `inventory`;
  `receive` выполняется только через сессию; плагины могут
  добавлять свои типы).
- **Batch** — группа заданий по разным блокам, созданных одной
  операцией подбора.
- **Резерв** — временное «удержание» товара в ячейке за активным
  заданием.
- **Руководитель** — `owner`, `admin`, `operator`.
- **Сотрудник** — рабочая учётка. Встроенные роли: `picker`,
  `receiver`, `putaway`, `inventory`. Плагины могут
  регистрировать дополнительные роли.
- **TLS/HTTPS** — шифрование канала между сервером и клиентами.
- **Fingerprint** — отпечаток сертификата (`base64url(sha256(der))`),
  передаётся в QR (`WMS://ip:port#fp=...`).
- **Pinning** — клиент доверяет только одному сохранённому
  сертификату, а не системным CA.
- **TOFU** — Trust On First Use: при первом скане QR клиент
  сверяет сертификат с fingerprint из QR и запоминает его.

## 4. Лаунчер (список складов)

Открывается при запуске `python main.py`.

### 4.1. Верхняя строка

| Элемент | Действие |
|---|---|
| **Заголовок** «Список складов» | Подпись, не нажимается. |
| **Кнопка «+»** (зелёная) | Открывает мастер создания склада. |
| **Кнопка «↗»** (синяя) | Открывает диалог входа в удалённый сервер (адрес — из `config.json` → `last_server`). |
| **Комбобокс «Язык:»** | **Все** языки из `lang/` (Русский, English, Deutsch, … + языки из `plugins/*/lang/`). Меняет язык лаунчера немедленно; сохраняется в `config.json`. |

Языки в селекторе появляются после перезапуска лаунчера — если
добавили новый `lang/*.json` в работающий экземпляр, нужен
перезапуск.

### 4.2. Список складов

- Показывается каждая папка в `warehouses/`, содержащая
  `warehouse.db`.
- Пустой список → надпись «Нет созданных складов!».
- **Клик по складу** открывает диалог «Открыть склад» с тремя
  кнопками:

| Кнопка | Что делает |
|---|---|
| **«Сервер + клиент»** | Запускает сервер в фоне, ждёт `/ping` (по HTTP или HTTPS в зависимости от `settings.tls_enabled`), открывает окно статуса сервера, затем окно входа ПК-клиента. |
| **«Только сервер»** | Запускает сервер, открывает только окно статуса; ПК-клиент не запускается. |
| **«Отмена»** | Ничего не делает, диалог закрывается. |

### 4.3. Ошибки лаунчера

При неудачном запуске сервера лаунчер показывает диалог «Ошибка
сервера» с последними 1500 символами вывода процесса. При
некорректном завершении дочернего процесса — «Ошибка клиента»,
«Ошибка мастера» или «Ошибка сервера» с тем же принципом.

## 5. Мастер создания склада

Открывается по «+» в лаунчере или `python utils/setup.py`.

### 5.1. Страница 1 — основные параметры

| Поле | Описание | Правила |
|---|---|---|
| **Наименование** | Имя папки склада | Только латиница, цифры, `_`. Не пустое. |
| **Префикс рабочей тары** | Строка перед ШК тары | Опционально. |
| **Суффикс рабочей тары** | Строка после ШК тары | Опционально. |
| **Префикс ШК ячейки** | Строка перед ШК ячейки | Опционально. |
| **Суффикс ШК ячейки** | Строка после ШК ячейки | Опционально. |
| **Количество блоков** | 1..9 | Обязательно. |
| **Количество этажей** | 1..9 | Обязательно. |
| **Количество рядов** | 1..99 | Обязательно. |
| **Количество секций** | 1..99 | Обязательно. |
| **Включить TLS (HTTPS)** | Чекбокс, по умолчанию **включён** | При включении генерируется самоподписанный сертификат; сервер работает по HTTPS. Настоятельно рекомендуется для локальной сети. |

Кнопки:
- **«Далее»** — валидирует поля, переходит на страницу 2.
- **«Отмена»** — закрывает мастер без создания склада.

### 5.2. Страница 2 — владелец склада

| Поле | Описание | Правила |
|---|---|---|
| **Логин*** | Логин руководителя-владельца | Только `a-z 0-9 _ .`. Не пустой. |
| **Пароль*** | Пароль владельца | Минимум **8 символов**. Хранится как PBKDF2-SHA256. |
| **Повтор*** | Повтор пароля | Должен совпадать. |

Кнопки:
- **«← Назад»** — возврат на страницу 1.
- **«Далее»** — валидирует, переходит на страницу 3.
- **«Отмена»** — закрывает мастер.

### 5.3. Страница 3 — подтверждение

Показывает сводку: наименование, блоков, этажей, рядов, секций,
владелец, статус TLS.

Кнопки:
- **«← Назад»** — на страницу 2.
- **«Подтвердить»** — создаёт БД, генерирует ячейки, создаёт
  владельца (и сертификат при TLS); переходит на страницу 4
  (прогресс).
- **«Отмена»** — закрывает мастер.

### 5.4. Страница 4 — прогресс и результат

- **Прогресс-бар** — процент создания ячеек.
- **Статус-метка** — «Создание БД…», «Генерация TLS-сертификата…»
  (если включён TLS), «Генерация ячеек: N/M», «База данных
  успешно создана».
- **Результат** — путь к папке склада. При TLS — дополнительно
  fingerprint сертификата.
- **Кнопка «Закрыть»** — доступна после успеха или ошибки; закрывает
  мастер.

При ошибке показывается диалог «Ошибка» с трассировкой (последние
1000 символов).

## 6. Окно статуса сервера

Открывается при старте сервера в любом режиме. Обновляется раз
в 2 секунды (POST `/status`). При TLS — по HTTPS с сертификатом
из папки склада.

### 6.1. Поля

| Поле | Описание |
|---|---|
| **URL** | Адрес сервера (`http://` или `https://`). |
| **Состояние** | 🟢 «Работает · HH:MM:SS» / 🔴 «Сервер недоступен» / 🔴 «Ошибка сервера». |
| **База данных** | Название папки склада. |
| **Админ-клиенты** | Количество руководителей, активных за последние 60 сек. |
| **Рабочие клиенты** | Количество сотрудников, активных за последние 60 сек. |
| **По устройствам** | `pc: N, android: M`. |
| **Uptime** | ЧЧ:ММ:СС с момента запуска. |
| **Потоков** | Количество активных потоков Python. |
| **Запросов/сек** | Число запросов за текущую секунду. |
| **Запросов за час** | Сумма за последние 60 минут. |
| **Запросов за день** | Сумма за последние 24 часа (по минутным срезам). |
| **Принято/сек, Отправлено/сек** | Байты в секунду. |
| **Принято/Отправлено за час** | Байты за час. |
| **Принято/Отправлено за день** | Байты за сутки. |
| **Всего принято/отправлено** | С момента запуска сервера. |

### 6.2. Кнопки

- **«Остановить сервер»** — открывает подтверждение «Остановить
  сервер? Все клиенты потеряют связь.» → kill процесса, показ
  лаунчера.
- **Крестик окна** — закрывает окно; сервер продолжает работать.
- Язык фиксируется при создании окна и не меняется до перезапуска.

## 7. ПК-клиент управления: общее

### 7.1. Диалог входа

Открывается при выборе «Сервер + клиент» или «↗ Удалённый клиент».

| Поле | Описание |
|---|---|
| **Сервер** | Адрес сервера (`http://ip:8765` или `https://ip:8765`). При локальном запуске — `http(s)://127.0.0.1:8765`. |
| **Логин** | Логин руководителя. |
| **Пароль** | Пароль. Скрыт точками. Enter — то же, что «Войти». |

Кнопки:
- **«Войти»** — POST `/mgmt/login`; при успехе запрашивает
  `/mgmt/me` и открывает окно.
- **«Отмена»** — закрывает клиент.

Ошибки:
- «Заполните все поля.» — если что-то пусто.
- «Сервер недоступен: {ошибка}» — сеть.
- «Неверный логин или пароль.» — 200 + `ok:false`.
- «Сервер не выдал токен.» — некорректный ответ.
- «Ошибка профиля: {ошибка}» / «Не удалось получить профиль.»
- «Слишком много попыток, подождите N сек» — rate-limit
  (10 неудачных попыток за 5 минут → блок на 15 минут).

### 7.2. Сайдбар

Фиксированная ширина 220 px, тёмно-синий фон. Сверху — логотип
(или надпись «ЛУЧ», если нет `logo_horizontal.png`).

Под логотипом:
- Плашка **«SAFE MODE»** (жёлтая) — только в безопасном режиме.
- Плашка **REMOTE** с адресом сервера — только в удалённом режиме.
- Плашка с логином/ролью текущего руководителя.
- В заголовке окна — суффикс **[TLS]**, если сервер работает по HTTPS.

Пункты меню (сверху вниз):

| Пункт | Ключ | Роли |
|---|---|---|
| 📦 Просмотр склада | `viewer` | все |
| 📋 Задания | `tasks` | все |
| 🏷 Артикулы | `items` | все |
| 📦 Тары | `containers` | все |
| 📍 Точки сброса | `drop_points` | все |
| 🔔 Уведомления | `notifications` | все |
| ⚙ Настройки | `settings` | `owner`, `admin` |
| 👤 Сотрудники | `employees` | `owner`, `admin` |
| 🔑 Руководители | `managers` | `owner` |
| 🧩 Плагины | `plugins` | `owner`, `admin` |
| О программе | `about` | все |

**Плагинные страницы** добавляются **сверху** (после `about`,
если роль подходит). При активации плагина страница появляется
в сайдбаре сразу, без перезапуска клиента. При деактивации —
исчезает.

У «Уведомлений» есть динамический бейдж `(N)` — количество
непрочитанных уведомлений в БД (обновляется раз в 10 сек).

Роли `operator` не видят пунктов, недоступных по роли, — эти
кнопки не создаются в сайдбаре вообще.

### 7.3. Заголовок окна

`Луч — <склад> [login / role]`, в удалённом режиме ещё
`[удалённый] <url>`. В safe mode — суффикс `[SAFE MODE]`,
при TLS — `[TLS]`.

### 7.4. Универсальные элементы страниц

Все страницы — тонкие клиенты. Они отправляют POST на
`/mgmt/page/{key}` для загрузки и `/mgmt/page/{key}/action` для
действий. Поля `values` собираются со всех полей на странице.

Универсальные элементы:

- **Поле поиска** (`kind="text"`, `on_change="input_submit"`) —
  фильтрует таблицу; обновление по мере ввода с задержкой.
- **Select-фильтр** (`kind="select"`, `on_change="input_submit"`) —
  обновление по выбору.
- **Checkbox-фильтр** — переключатель, обновление сразу.
- **Кнопка «Обновить»** — перерисовка с текущими значениями полей.
- **Двойной клик по строке таблицы** — открывает панель/карточку.
- **Кнопка «← Назад»** — возврат к списку.

## 8. ПК-клиент: Просмотр склада

### 8.1. Список ячеек

Заголовок «Просмотр склада» + хлебная крошка «Главная».

| Элемент | Действие |
|---|---|
| **Поле «Поиск:»** | Фильтр по адресу, ШК или типу ячейки. |
| **Кнопка «Обновить»** | Перезагрузка с текущим фильтром. |
| **Таблица «Ячейки»** | Колонки: адрес, кол-во товаров, ШК ячейки, тип. |
| **Двойной клик по строке** | Открывает карточку ячейки. |

### 8.2. Карточка ячейки

Заголовок «Ячейка: <адрес>» + хлебная крошка «Главная → <адрес>».
Клик по «Главная» возвращает к списку.

**Левая колонка:**
- Превью ШК (Code128).
- Текст ШК.
- Кнопка **«Скачать стилизованный ШК»** — сохраняет PNG с
  заголовком «ЯЧЕЙКА», адресом и ШК.

**Правая колонка — «Характеристики ячейки»:**
- Адрес.
- Тип.
- Всего (сумма по `placed_instances` в этой ячейке).

**Панель действий (ниже):**
- Поле **«Поиск:»** (id `cell_search:<адрес>`) — фильтр по
  содержимому ячейки (артикул/название/ШК).
- Кнопка **«Подбор»** — открывает диалог подбора.
- Кнопка **«Размещение»** — открывает диалог размещения.
- Кнопка **«Инвентаризация»** — открывает диалог инвентаризации.

**Таблица содержимого:** артикул, название, штрихкод, количество.

### 8.3. Диалог «Подбор»

Открывается по кнопке «Подбор» в карточке ячейки. Заголовок
«Подбор». Внутри:
- Текст «Выберите рабочую тару:».
- Таблица тар: ШК, тип, статус, содержимое. Только тары со
  статусами `free`, `waiting`, `placing`. Поиск по таблице.

Кнопки:
- **«Выбрать»** — если тара выбрана, открывает второй диалог
  «Подбор» с таблицей содержимого ячейки.
- **«Отмена»** — закрывает диалог.

Если тар нет — вместо диалога открывается предупреждение «Нет
доступных тар для подбора».

### 8.4. Диалог «Подбор» — редактирование количества

Заголовок «Подбор». Внутри:
- Текст «Источник: <ШК ячейки> → Цель: <ШК тары>».
- Подсказка «Дважды кликните на количество, чтобы изменить.»
- Редактируемая таблица: артикул, название, количество.

Кнопки:
- **«Выполнить»** — перемещает указанные количества из ячейки в
  тару; статус тары обновляется (если была `free` — станет
  `waiting`).
- **«Отмена»** — возврат в карточку ячейки.

Ошибки: «Недостаточно товара <code>» — если в ячейке не хватает.

### 8.5. Диалог «Размещение»

Аналогичен подбору, но:
- Показывает только тары со статусом не `picking`, не `accepting`,
  не `unknown_scan`, у которых есть товары.
- Кнопка «Выбрать» → диалог редактирования количества с источником
  «тара», целью «ячейка».

**«Выполнить»** — перемещает товар из тары в ячейку; автоматически
отменяет активные putaway-задания на эту тару (если после
перемещения тара стала пустой — переводит в `free`).

### 8.6. Диалог «Инвентаризация»

Открывается по «Инвентаризация» в карточке. Заголовок
«Инвентаризация». Внутри:

## 9. ПК-клиент: Задания

### 9.1. Список заданий

Заголовок «Задания», справа — «+ Создать задание» (открывает
мастер).

**Карточка «ШК сервера»:**
- QR-код (для сканирования ПК-терминалом и ТСД). При TLS —
  с `#fp=<fingerprint>`.
- Текст `URL: WMS://<ip>:8765` (или `WMS://<ip>:8765#fp=...`).
- Подсказка «Отсканируйте этот QR в клиенте, затем — QR
  с пропуска сотрудника.»

**Панель фильтров:**

| Поле | Описание |
|---|---|
| **Поиск:** | По номеру задания или исполнителю. |
| **Тип:** | Все / pick / receive / putaway / inventory (+ типы от плагинов, если они есть в списке). |
| **Статус:** | Все / pending / in_progress / action_required / done. |
| **Платформа:** | Все / ПК / ТСД. |

| **Дата:** | Все / Сегодня / За 7 дней. |
| **Обновить** | Перезагрузка с текущими фильтрами. |

Фильтры сохраняются только в текущем документе; при переходе на
другую страницу сбрасываются.

**Таблица:** номер (с «(B<блок>)» и «⚠» для частичных), тип,
платформа, прогресс, исполнитель, статус.

**Двойной клик по строке** → панель задания.

### 9.2. Панель задания

**Две колонки:**
- Слева: превью ШК (Code128), номер под ним.
- Справа — карточка «Сведения»:
  - Номер.
  - Тип (локализованный).
  - Платформа (Любая / ПК / ТСД).
  - Статус (Ожидание / Выполняется / Требуются действия /
    Завершено).
  - Исполнитель (или «—»).
  - Частичное: «⚠ Да» или «Нет».
  - Блок (или «—»).

  связанные `task_items`, `task_events`, `reservations`;

  `placing`.

### 9.4. Мастер создания задания

Кнопки:
- **«Добавить»** — добавляет (или суммирует с существующей

- **«Добавить»** — добавляет тару; ошибка «Такая тара уже
  добавлена» выводится внутри диалога.

### 9.7. Диалог «Добавить ячейку»

- **Таблица всех ячеек** (адрес + ШК) с поиском. Выбор — клик
  по строке + «Добавить».
- Ошибки («Выберите ячейку из таблицы», «Ячейки с ШК… не
  существует», «Такая ячейка уже добавлена») — внутри диалога.

### 11.2. Панель тары

### 11.3. Диалог «Создать тару»

  (с префиксом/суффиксом склада).
- Подсказка о статусе и генерации.
- **«Создать»** — создаёт тару. Проверки: уникальность ШК;
  ошибка «Такой ШК уже существует: <code>».

### 11.4. Диалог «Приёмка без задания»

Открывается по кнопке «Приёмка без задания».

**Содержимое:**
- Подсказка «Выберите тару в таблице ниже, затем укажите
  количество для нужных артикулов и нажмите «Принять»…».
- **Таблица тар** (`field_id="table_containers"`): ШК тары +
  статус. Поиск по ШК/статусу. Только статусы `free`/`accepting`.
- **Таблица товаров** (`field_id="table_items"`): артикул,
  название, количество (редактируемое). Поиск.

Кнопки:
- **«Принять»** — берёт контейнер из `table_containers_selected`,
  товары — из `table_items`. Увеличивает `placed_instances`,
  переводит тару в `placing`.
  - Ошибки: «Выберите тару в таблице», «Введите количество хотя
    бы для одного артикула», «Тара <bc> в статусе <st>. Ожидается
    free или accepting.»
- **«Отмена»**.

### 11.5. Вывести из оборота

- **Кнопка «Вывести из оборота»** — требует выбранную строку в
  таблице (выделение). Иначе — ошибка «Выберите тару.»
- Если тара размещена на точке сброса → ошибка «Тара <bc>
  сброшена на точку <placed_in>. Освободите её через «📍 Точки
  сброса».»
- Если статус `picking` → ошибка «Тара в работе (статус:
  picking). Сначала завершите или отмените задание.»
- Если статус `accepting` → открывается диалог «Вывод из
  оборота»:
  - Текст с перечнем удаляемых позиций и итоговым количеством.
  - Кнопка **«Освободить принудительно»** (красная) — очищает
    `placed_instances` и переводит тару в `free`.
  - **«Отмена»**.
- Иначе (пустая и не принимающая) — ошибка «В таре нет товаров.
  Для удаления используйте «Удалить».»

### 11.6. Удалить тару

- **Кнопка «Удалить»** — только для тар со статусом `free` или
  `accepting` без `placed_in`.
- Иначе — ошибки:
  - «Тара размещена в ячейке или сброшена на точку.» (placed_in)
  - «Удалять можно только свободные тары. Текущий статус: <st>.
    Используйте «Вывести из оборота».»
  - «Тара не пуста (N шт). Используйте «Вывести из оборота».»

## 13. ПК-клиент: Уведомления

### 13.1. Список уведомлений

Заголовок «Уведомления», справа «+ Написать», «Отметить всё
прочитанным».

| Элемент | Действие |
|---|---|
| **Поле «Поиск:»** | Фильтр по тексту или отправителю. |
| **Показывать прочитанные** | Чекбокс. По умолчанию выключен — показываются только непрочитанные (`read_at=''`). |
| **«Обновить»** | Перезагрузка с текущими полями. |
| **Таблица** | Дата, тип, от кого, кому, текст, прочитано. |
| **Двойной клик** | Открывает диалог деталей. |

`mark_all` («Отметить всё») и `mark_read` помечают прочитанными

не «сжигают» inbox конкретных сотрудников.

Если в сообщении остались `{name}` (старое уведомление или плагин
сохранил шаблон), при отображении в списке и в деталях
подставляются значения из `payload.params`.

### 13.2. Диалог «Написать»

Заголовок «Новое уведомление».

| Поле | Описание |
|---|---|
| **Получатель:** | Всем сотрудникам / По роли / Конкретному сотруднику. |
| **Роль:** | Только при «По роли». **Все** роли из реестра (встроенные + от плагинов). |
| **Таблица сотрудников** | Только при «Конкретному». Колонки: логин, ФИО. Поиск. |
| **Тип:** | Информация / Срочно (со звуком и вибрацией). |
| **Текст:** | Многострочное текстовое поле. Обязательно. |

Кнопки:
- **«Отправить»** — создаёт по строке `notifications` на каждого
  получателя; `sender_login` = логин текущего руководителя.
- **«Отмена»** — закрывает диалог.

Ошибки: пустое поле → сообщение «Введите текст» (поле
сохраняется); нет получателей → тихая перезагрузка без отправки.

### 13.3. Диалог деталей

Заголовок = тип уведомления («🔔 Информация», «🔴 Срочное

Кнопки:

## 14. ПК-клиент: Настройки

Заголовок «Настройки склада».

### 14.1. «Язык интерфейса»

- **Селект «Язык»** — все доступные языки (включая `de.json` и
  языки плагинов). При выборе сохраняется персонально для
  текущего руководителя (`_mgmt_locale_<login>`), применяется
  ко всем страницам этого админа. Не влияет на других
  руководителей и на сотрудников.
- **Кнопка «Перечитать lang/»** — перезагружает словари без
  перезапуска сервера.

### 14.2. «Безопасность»

Доступно owner и admin. Отображает:

- **Бейдж режима:** «Режим: HTTPS (TLS)» (зелёный) или
  «Режим: HTTP» (жёлтый).
- **Бейдж сертификата:** «Сертификат: установлен» или
  «Сертификат: отсутствует».
- **Fingerprint** сертификата (`base64url(sha256(der))`) —
  тот, что попадает в QR. Если сертификата нет — «—».
- **Чекбокс «Использовать TLS (HTTPS)»** — сохраняет настройку
  в `settings.tls_enabled`. **Требует перезапуска сервера**
  (остановить в окне статуса → запустить заново).
- **Кнопка «Перевыпустить сертификат»** — доступна, если серт
  есть. Открывает диалог подтверждения:
  - старый сертификат сохраняется как `cert.pem.old` (30 дней);
  - генерируется новый;
  - в сообщении показывается новый fingerprint;
  - **все клиенты должны заново отсканировать QR** с новым
    fingerprint;
  - **требуется перезапуск сервера**.

Подсказка под карточкой: «Включение/выключение TLS и перевыпуск
сертификата требуют перезапуска сервера. После изменения
перезапустите сервер вручную (остановить в окне статуса и
запустить заново).»

### 14.3. «Блоки склада»

- **Селект блока** (существующие блоки).
- **«Создать блок»** — открывает диалог создания (только если
  есть свободные номера 1..9).
- **«Удалить блок»** — удаляет выбранный блок, если в нём нет
  ячеек. Иначе — ошибка «В блоке N ячеек. Сначала удалите их.»

Подсказка «Все блоки (1-9) уже созданы» — при отсутствии
свободных номеров (кнопка «Создать блок» становится
недоступной).

**Диалог «Новый блок»:**
- Селект с номерами свободных блоков.
- **«Создать»** — добавляет `blocks(name)`.
- **«Отмена»**.

### 14.4. «Диапазон ячеек»

- **Этажи (от—до)** — два number-поля, 1..9.
- **Ряды (от—до)** — два number-поля, 1..99.
- **Секции (от—до)** — два number-поля, 1..99.

Значения сохраняются в `settings` при `input_submit` и
восстанавливаются при следующем открытии.

### 14.5. «Структура ячеек в секции»

- **Количество полок** — number, 1..26 (по умолчанию 1).
- Для каждой полки (A, B, C, …) — поле **«Полка X:»** (number,
  1..99) — количество ячеек в полке.

При изменении количества полок — страница перерисовывается с
соответствующим набором полей.

### 14.6. Кнопки «Создать диапазон» / «Удалить диапазон»

**«Создать диапазон»** — создаёт ячейки для выбранного блока в
указанных этажах/рядах/секциях по каждому полочному шаблону
(например, `A1..A5`, `B1..B3`). Уже существующие адреса
пропускаются. Сообщение «Создано: N. Пропущено: M.»

**Серверная валидация:**
- Этаж/ряд/секция/полки — 1..9 / 1..99 / 1..26 / 1..99.
- Лимит **2 000 000 ячеек** за одну операцию.
- Если ячеек > **50 000** — открывается диалог подтверждения
  «Будет создано N ячеек… Продолжить?».
- Если ячеек > **200 000** — в диалоге дополнительная подсказка:
  «Рекомендуем создавать по этажам: укажите «Этаж от = Этаж до»
  для одного этажа, затем повторите для следующего».
- Если ячеек > 2 000 000 — ошибка «Слишком большой диапазон
  (N ячеек). Максимум 2 000 000 за раз…».

**«Удалить диапазон»** — удаляет ячейки в выбранном диапазоне,
если в них нет товаров. Иначе — ошибка «Есть товары в ячейках:»
с перечнем адресов (первые 10).

## 19. ПК-терминал

Запуск: `cd client_desktop; python main.py`. Ищет `icon.png` и
`logo_horizontal.png` сначала в папке `client_desktop/`, затем в
родительской.

### 19.1. Экран «QR-код сервера»

- **Логотип** сверху.
- **Заголовок** «Отсканируйте QR-код сервера».
- **Подсказка** «(QR находится в разделе «Задания» в панели
  «ШК сервера»)».
- **Комбобокс «Язык:»** — переключает язык всех строк клиента
  немедленно. Доступные языки: ru, en + любые из
  `config.json.ui_cache[<server>].config.locales`.
- **Бейдж режима:** «🔒 HTTPS» (зелёный) или
  «⚠ HTTP (без шифрования)» (жёлтый) — после успешного
  подключения к серверу.
- **Сканер** — сканирование QR формата `WMS://host[:port]/`
  (HTTP) или `WMS://host[:port]#fp=<fingerprint>` (HTTPS).
  - При HTTPS клиент выполняет TOFU: забирает сертификат с
    сервера, сверяет fingerprint с `#fp=`, сохраняет PEM в
    `config.json.tls_certs[<server>]`. Все последующие запросы
    идут только к этому сертификату (pinning).
  - При несовпадении — ошибка «Сертификат сервера не совпадает
    с QR. Возможна MITM-атака…» и подключение не выполняется.
  - При успехе — синхронизация `ui_config` (проверка версии
    через `/ui_config/version`, при изменении — полная
    загрузка), затем переход на «QR сотрудника».
  - Неверный QR → диалог «Это не QR-код сервера:\n<code>».

### 19.2. Экран «QR с пропуска»

- Логотип.
- Заголовок «Отсканируйте QR с пропуска».
- Подсказка «Поднесите QR сотрудника к сканеру».
- Статус ошибок (красный).
- Кнопка **«Сменить сервер»** — возврат на экран QR сервера.

**Сканер:** ожидает строку `login-secret`. Успех → `POST /login`
(сервер возвращает opaque-токен), `/employees/me`,
`/capabilities/hello`, `/settings` (при недоступности — fallback
на `settings_cache` из `config.json`); переход на режимы.
Ошибки: «Это не QR сотрудника», «Доступ запрещён: …»,
«Слишком много попыток входа» (rate-limit).

### 19.3. Экран режимов

- **ФИО** пользователя.
- **Роли** через запятую, либо «Нет назначенных ролей,
  обратитесь к руководителю» (красный).
- **«Выйти»** — закрывает сессии (с force), отзывает токен на
  сервере (`POST /logout`), сбрасывает токен, возврат на
  QR-сервера.
- **Блок «Сессии»** — кнопки вида «▶ Сессия приёмки» (только
  если у сотрудника есть роль `receiver`).
- **«Получить задание»** — блокируется, пока идёт запрос.
- Подсказка «Сессии — это длинные процессы (например, приёмка).
  Задания берутся кнопкой выше.»

### 19.4. Экран сессии (приёмка)

- Заголовок = название сессии.
- **«Закрыть сессию»** — предварительная попытка
  `POST /sessions/{key}/close` (без force). Если сервер
  отказывает (есть открытая тара или грузоместо) — сообщение
  с причиной, остаётся на экране.
- **View:** статус (тара/грузоместо/принято), кнопки по
  контексту («Закрыть рабочую тару», «Отменить тару»,
  «Закончить грузоместо», «Частичное завершение», «Отменить»),
  таблица товаров в грузоместе, при role_revoked — предупреждение
  и авто-закрытие сессии после закрытия тары.
- **Сканер** — см. раздел 21.

### 19.5. Экран задания

- Заголовок `Задание TASK-NNNNNN`.
- **«Выйти»** — отпускает задание (`cancel`), возвращает к
  режимам.
- Плашка **«Блок XX · Часть N из M»** — если задание из batch.
- **View** — рендер шага задания.
- **Сканер** — сканы товаров/ячеек/тары.
- При `finished=true` — сообщение «Задание выполнено», возврат к
  режимам.
- При `not_found_result` — диалог «Найдено рядом / Найдено
  частично / Товар утерян» с ячейкой и/или новым номером задания.

### 19.6. Оверлей «Нет связи»

- Затемнение всего окна.
- Карточка с «Нет связи с сервером».
- **«Попытка: N»**, **«Последний контакт: N сек назад»**,
  **«Переподключение…»**.
- Пока оверлей активен, работа блокируется.

При восстановлении связи: интервал heartbeat возвращается к 5
сек, если открыт экран задания — view перезапрашивается
(`task_view`), если сессия — `sessions_start` для свежего
состояния.

### 19.7. Snackbar и уведомления

- Snackbar — короткие серые плашки снизу по центру,
  исчезают через 3.5 сек.
- **Диалог уведомления:** заголовок «🔔 Уведомление» /
  «🔴 СРОЧНО», отправитель, дата, текст, кнопка
  **«Прочитано»** — закрывает и отправляет `mark_read` на сервер.

Запуск — приложение `WMSClient` (APK). Первый запуск — экран
выбора типа устройства. Дальше — экран QR сервера, QR пропуска,
режимов, задания, сессии (если доступна), «Выполнено».

Клиент работает в двух режимах сканирования, которые выбираются
один раз при первом запуске (и меняются из drawer → «Настройки
сканера»):

| Режим | Устройство | Как сканирует |
|---|---|---|
| **ТСД** (`pda`) | терминал сбора данных с HID-сканером | сканер как клавиатура; клиент перехватывает ввод через `dispatchKeyEvent` |
| **Телефон** (`phone`) | Android-смартфон/планшет с камерой | встроенное превью камеры в окне задания/сессии |

### 20.1. Экран «Настройки сканера»

- Открывается **автоматически при первом запуске** (без кнопки
  «Назад» — выбор обязателен).
- В любой момент доступен из drawer → **«Настройки сканера»**.
- Две карточки: **«ТСД — терминал сбора данных»** и
  **«Android-устройство без сканера»**. Радиокнопка + описание.
- Выбор сохраняется в `SharedPreferences` (`device_type`).
- На маленьких экранах страница прокручивается — карточки не
  обрезаются.

### 20.2. Экран QR сервера

- Логотип `R.drawable.logo_horizontal` (пре-скейлится один раз
  при первом показе).
- Заголовок «Отсканируйте QR-код сервера» / адрес сервера, если
  уже сохранён.
- Подсказка «(QR находится в разделе «Задания» в панели «ШК
  сервера»)».
- Сканирование:
  - **ТСД** — HID-сканером (ввод идёт как клавиатура, Enter —
    конец строки).
  - **Телефон** — кнопка **«📷 Сканировать»** снизу; открывается
    полноэкранный `CaptureActivity` (zxing), после скана
    возвращается на экран.
- **QR с TLS:** `WMS://host:port#fp=<fingerprint>`. Клиент:
  - Если серт сохранён и `#fp=` нет — использует сохранённый
    HTTPS.
  - Если `#fp=` есть и серт не сохранён — TOFU: забирает серт,
    сверяет, сохраняет PEM в `SharedPreferences "wms_certs"`.
  - Если `#fp=` не совпадает с сохранённым — диалог «сертификат
    изменился», требует подтверждения пользователя.
  - Если HTTPS, но `#fp=` нет и серта нет — ошибка «Сервер
    использует HTTPS, но в QR нет fingerprint…».
- При успехе клиент подключается к серверу: `POST /ui_config/version`
  → при изменении `POST /ui_config` → кэш + применение. Дальше —
  `POST /login`, `/settings` (fallback на кэш), `/capabilities/hello`.
- Переключение языка — из drawer (иконка «Язык»).

### 20.3. Экран QR пропуска

- Логотип.
- «Отсканируйте QR с пропуска».
- Ошибки — красным.
- **«Сменить сервер»** — возврат на экран QR сервера.
- Сканирование — так же, как 20.2 (ТСД — HID, телефон —
  полноэкранный `CaptureActivity`).

### 20.4. Экран режимов

- ФИО и роли (перевод через `ui_config.roles` и `Lang.t`).
- **«Выйти»** — отзывает токен на сервере (`api.logout()`),
  очищает локальное состояние.
- Сессии (те, что `platforms` включают `android`; встроенная
  сессия приёмки — только `pc`, поэтому на Android не
  показывается).
- **«Получить задание»**.

### 20.5. Экран задания

- Заголовок с номером задания.
- Плашка «Блок … · Часть N из M» (если batch).
- View задания (что сканировать, сколько осталось, подсказки).
- **«Выйти»** (отпускает задание).
- Сканирование:
  - **ТСД** — HID-сканером, без экранных элементов.
  - **Телефон** — **встроенное превью камеры** внизу экрана
    (высота ~240 dp). Вверху — само задание, видно, что и
    сколько нужно сканировать. Сканирование непрерывное с
    кулдауном **1 секунда** между срабатываниями (защита от
    «автомата» при наведении на несколько меток сразу).
  - Первый запуск в режиме «телефон» → запрос разрешения на
    камеру. Если отклонено — в блоке сканера «Нет доступа к
    камере» и кнопка «Разрешить».
- Диалог `not_found_result` после обработки (найдено рядом /
  частично / утеряно).

### 20.6. Экран сессии (если сессия доступна на Android)

- Аналогичен экрану задания: сверху — view сессии, снизу —
  встроенный сканер (в режиме «телефон»).

### 20.7. Экран «Выполнено»

- Заголовок «Задание выполнено».
- Тип и номер задания.
- **«К режимам»**.

### 20.8. Оверлей «Нет связи»

Аналогичен ПК-терминалу: блокирует работу, показывает попытку,
последний контакт, «Переподключение…». При восстановлении связи
автоматически перезапрашивает view текущего шага.

Heartbeat: **10 секунд** в норме, **2 секунды** пока офлайн
(чтобы быстрее заметить восстановление). После **3 неудач
подряд** — переход в офлайн.

### 20.9. Уведомления

Диалог уведомления. Для `urgent` — вибрация + звуковой сигнал.
**«Прочитано»** — закрывает и `mark_read`.

### 20.10. Меню (drawer)

- Логотип, ФИО, роли.
- Пункты: **«Настройки сканера»**, **«Язык»**, пункты с сервера
  (`menu.items` из `/ui_config`, фильтр по ролям), **«Выйти»**.
- Ширина drawer — 240 dp, анимация открытия/закрытия — 120 мс
  линейная (на слабых ТСД ощущается как мгновенная).
- В режиме первого запуска (когда выбор устройства ещё не
  сделан) drawer недоступен.

## 21. Сессия приёмки

Открывается кнопкой «▶ Сессия приёмки» на экране режимов
(только при роли `receiver`). Работает на ПК-терминале. На
Android сессия приёмки недоступна (фильтр `platforms=("pc",)`).

### 21.1. Цикл

1. **Скан тары.** Если статус тары `free` — переходит в
   `accepting`, привязывается к сессии. Если тара занята —
   ошибка «Тара занята (<st>)».
2. **Скан грузоместа.** Строка `TASK-NNNNNN` типа `receive`.
   Если задание не найдено → «Грузоместо <bc> не найдено».
   Если уже `done` → «Грузоместо уже обработано». Если
   назначено другому → «Грузоместо назначено: <login>».
   Успех → задание `in_progress`, `assignee_login=<login>`.
3. **Сканы товаров.** Каждый скан:
   - Известный ШК/артикул → `scanned_qty += 1`,
     `processed_a += 1`, товар добавляется в тару.
   - ШК известен, но не в задании → «Принято сверх плана:
     <barcode>», добавляется как `extra`.
   - Неизвестный ШК → «Неизвестный ШК «<bc>». Отложите товар
     и сообщите руководителю.», событие `rejected`.
4. **«Закончить грузоместо»** — переводит сессию в pending
   `finish_cargo`, запрашивает скан ШК грузоместа.
   - Не всё принято → «Принято не всё (p/t). Используйте
     «Частичное завершение».»
   - Всё принято → задание `done`, `assignee_login=NULL`,
     резервы освобождаются, сессия возвращается в рабочий
     режим.
5. **«Частичное завершение»** — pending `partial_cargo`. При
   скане ШК грузоместа:
   - Ничего не принято → «Нечего завершать: ни один товар не
     принят.»
   - Принято частично → принятые позиции фиксируются в
     `task_events` (`receive_done`), остаток вычитается из
     `task_items`, `processed_a` сбрасывается в 0,
     `partial=1`, `status='pending'`. Сообщение «Остаток N шт
     возвращён в очередь».
6. **«Закрыть рабочую тару»** — pending `finish_container`.
   - Есть активные грузоместа → «Сначала закройте все
     грузоместа (активных: N). Затем повторите закрытие тары.»
   - Тара пустая → `free`.
   - Тара с товаром → `placing`, создаётся putaway-задача
     (если ещё нет) или сообщение «уже в задании на
     размещение».
7. **«Отменить тару»** — только пока тара пуста.
8. **«Отменить»** (pending) — сбрасывает pending.

### 21.2. Отзыв роли

Если руководитель снял роль `receiver` у сотрудника:

- В сессии появляется предупреждающая карточка «⚠ Ваша роль
  приёмки отозвана».
- Кнопка «Отменить тару» скрыта.
- Кнопки «Закончить грузоместо» и «Закрыть рабочую тару»
  доступны — чтобы завершить текущую работу.
- После закрытия тары (и грузоместа) сессия закрывается
  автоматически.

### 21.3. Обрыв связи

Оверлей «Нет связи» блокирует работу. При восстановлении —
`POST /sessions/receive/start` для перезапроса view (это
работает как no-op refresh, состояние сервера сохраняется).

### 21.4. Закрытие сессии

- **«Закрыть сессию»** на экране сессии. Если есть открытая
  тара/грузоместо — сервер отказывает с явной ошибкой.
- При выходе из клиента (logout) сессии закрываются с
  `force=true`: активные грузоместа возвращаются в очередь,
  непустые тары переводятся в `placing` с автоматическим
  созданием putaway-задачи, чтобы не потерять товар.

## 22. Плагины: установка и активация

1. Скопировать **папку** плагина в `plugins/` (`plugin.json`,
   `plugin.py`, при необходимости — `lang/` и доп. файлы).
   Legacy одиночный `.py`-файл тоже работает.
2. ПК-клиент → «🧩 Плагины» → «Обновить».
3. Двойной клик по плагину → «Активировать».

Деактивация — там же. При деактивации снимаются hook'и,
mgmt-страницы, пункты меню ТСД, роли плагина; вызывается
`unregister(context)` (если плагин её объявил).

**Правило:** для всех режимов (включая удалённый и headless)
используйте `register_mgmt_page`. Устаревший `register_page`
(Qt-класс на клиенте) работает только в локальном режиме.

Активация хранится в `settings.active_plugins`. Деактивация
плагина не удаляет значения его ролей из `employees.roles` в
БД — они сохраняются при следующей правке карточки (см. «Роли
вне реестра»).

**Безопасность:** в 1.1.0 `PLUGIN_INFO` из legacy `.py`-файлов
читается через `ast.literal_eval` (без исполнения кода).
`entry` в `plugin.json` валидируется на `..` и абсолютные
пути — плагин не может выйти за пределы своей папки.

## 23. Безопасный режим

Запуск: `python utils/wms.py warehouses/<name> --safe`.

В safe mode:
- Плагины не активируются.
- Сервер запускается, все mgmt-разделы доступны.
- В сайдбаре — плашка «SAFE MODE».
- В «Плагинах» — предупреждающая плашка, кнопка «Активировать»
  заблокирована.

Используйте, если плагин сломал склад: заходите в safe mode,
деактивируйте проблемный плагин, перезапускайте без `--safe`.

## 24. Кэширование и актуальность

Оба клиента (ПК-терминал и Android) кэшируют `ui_config` и
`settings` локально. Проверка актуальности выполняется **только
при подключении к серверу**: старт приложения (если сервер уже
известен) или скан QR сервера. В течение сессии сеть для этих
запросов не дёргается.

### ПК-терминал (`client_desktop/config.json`)

| Ключ | Что |
|---|---|
| `ui_cache[<server>] = {version, config}` | полный `ui_config` (тема, экраны, языки, меню, роли) |
| `settings_cache[<server>\|<login>] = {settings}` | последние `/settings` |
| `tls_certs[<server>] = {fp, pem}` | сохранённый сертификат сервера (pinning) |
| `locale` | выбранный язык |
| `server` | URL последнего сервера |

Проверка версии: `POST /ui_config/version {version: <local>}` при
старте (фоном) и при скане QR. Если сервер вернул `changed: true` —
полная загрузка `/ui_config` и перезапись кэша.

`/settings` при логине: попытка сети (таймаут 8 сек), при
неудаче — fallback на `settings_cache`.

### Android (`SharedPreferences`)

| prefs | Ключ | Что |
|---|---|---|
| `wms_ui` | `version` + `config` | полный `ui_config` |
| `wms_locales` | `data` + `meta` | производные от `ui_config.locales` |
| `wms_settings` | `<server_url>` | последние `/settings` |
| `wms_certs` | `<server_url>` | PEM сертификата сервера (pinning) |
| `wms` | `locale`, `server`, `device_type` | локальные настройки |

Проверка версии: `POST /ui_config/version` при старте и при
скане QR. `/settings` при логине: сеть → fallback на
`wms_settings`.

### Что не кэшируется

Задания (`/tasks/*`), сессии (`/sessions/*`), уведомления
(`/notifications/*`), `/status`, `/ping` — не кэшируются.
Каждый запрос идёт на сервер.

### Добавление нового языка

1. Положить `lang/de.json` в папку `lang/` сервера.
2. **Перезапустить сервер.**
3. ПК-клиент: после следующего скана QR (или при старте, если
   сервер уже в `config.json`) — в селекторе «Язык» появится
   `Deutsch`.
4. Android: при следующем подключении к серверу (старт / скан
   QR) — `Deutsch` появится в drawer → «Язык».

## 25. FAQ

**«Не удалось занять порт 8765»** — сервер уже запущен.
Закройте старый экземпляр `main.py` или завершите процесс
вручную.

**«Неверный логин или пароль» (руководитель)** — проверьте
логин и пароль. Владелец создаётся при первом запуске мастера.
Других руководителей создаёт `owner` в разделе «Руководители».

**«Слишком много попыток, подождите N сек»** — сработал
rate-limit: 10 неудачных попыток за 5 минут → блок на 15 минут.
Это защита от брутфорса, действует на пару IP+логин.

**«Сервер недоступен»** — включён ли сервер? IP в QR
правильный? Порт 8765 не блокируется? Для удалённого клиента
правильный адрес (http или https)?

**«Сертификат сервера не совпадает с QR»** — возможна
MITM-атака. Если сервер действительно перевыпустил сертификат
(«Настройки → Безопасность → Перевыпустить сертификат»),
отсканируйте новый QR со страницы «Задания». Если не
перевыпускали — не подключайтесь, проверьте сеть.

**«Сервер использует HTTPS, но в QR нет fingerprint»** — QR
от старой версии клиента или скопирован вручную. Отсканируйте
QR со страницы «Задания» в ПК-клиенте управления (там
`#fp=...`).

**«Сертификат сервера изменился» (Android)** — сервер
перевыпустил сертификат. Нажмите «Доверять новому», если
перевыпуск делали вы; иначе — отказ.

**«Раздел «Руководители» отсутствует»** — только для роли
`owner`.

**«Не могу изменить роль владельца»** — роль `owner`
назначается только при создании склада, изменить или удалить
её нельзя.

**«Окно статуса не открылось»** — откройте `main.py` заново;
если сервер был запущен до обновления, старый процесс его не
покажет.

**«Удалённый клиент показывает неверное имя склада»** — сервер
отдаёт название из имени папки склада. Проверьте название
папки.

**«QProcess: Destroyed while process is still running»** —
значит, `main.py` завершился, не успев остановить дочерний
процесс. Обновлено: при закрытии все процессы убиваются.

**«Задание типа receive не появляется»** — это правильно.
Приёмка выполняется через сессию приёмки, а не через поток
заданий.

**«Приёмка: „Закончить грузоместо“ отклонено»** — принято не
всё. Досчитайте остаток или нажмите «Частичное завершение».

**«Приёмка: сессия не закрывается»** — сначала закройте
грузоместо и рабочую тару. Если тара непуста, force-close
переведёт её в `placing` и создаст putaway-задачу.

**«Язык в mgmt-клиенте не переключается»** — переключение
персональное, сохраняется за логином. Перезапуск клиента
сохраняет выбор.

**«Иконка ПК-терминала не отображается»** — положите `icon.png`
рядом с `client_desktop/main.py` (или в корне проекта). То же
для `logo_horizontal.png`.

**«Новый `lang/de.json` не появился в лаунчере»** — перезапустите
лаунчер (`main.py`). `i18n._load_all()` кэширует список языков
при первом обращении; кнопки «перезагрузить» в лаунчере нет.

**«Язык из `lang/de.json` не подхватился на ПК-терминале»** —
клиент читает `config.json.ui_cache[<server>]` — он обновляется
при скане QR или при старте (если сервер сохранён). Перезапустите
клиент.

**«На Android роль от плагина показывается как `role_audit`»** —
в приложении старая версия. Проверьте, что `WmsViewModel`
содержит `roleLabel()`, а `UiConfig` содержит `roles` (в
`/ui_config` ключ `roles`).

**«Плагинная страница открывается, но кнопки не работают»** —
в серверной части (`server.py::_mgmt_page_action`) должна быть
ветка `doc = result.get("view")` перед fallback на
`_mgmt_build_page`. Обновите сервер.

**«При активации плагина появилась ошибка `AttributeError: '_Ctx'
object has no attribute 'db'`»** — старая версия сервера.
Обновите `server.py`: `_get_plugin_context(plugin_name)`
возвращает настоящий `PublicContext` активированного плагина.

**«Кнопка «Обновить» в «Тарах» ничего не делает»** — работает
в 1.0.1+. Если у вас 1.0.0 — обновите клиент.

**«Уведомления исчезают из inbox сотрудника после «Отметить
всё» у админа»** — работает: админ-«Отметить всё» ставит
`read_at` только broadcast-уведомлениям.

**«В уведомлении виден текст `{barcode}`»** — работает:
при рендере подставляются значения из `payload.params`. Если
уведомление создано плагином без `payload` — проверьте, что
плагин кладёт `key` и `params` в `payload`.

**«Фото артикула из одной карточки попадает в другую»** —
временное фото привязано к (логин, mode, code) и очищается
при навигации.

**«Двойной клик по уведомлению → 500 Internal Server Error»** —
исправлено (был `KeyError: 0`).

**«Ручное размещение показывает тару, занятую в подборе»** —
тары в статусах `picking`/`accepting`/`unknown_scan` исключены
из диалога размещения.

**«Followup-задача после «Товар не найден» создаётся
android-only, хотя исходная была pc»** — followup наследует
`platform` исходной задачи.

**«После завершения putaway тары в статусе free, но с
товарами»** — непустые тары переводятся в `placing`.

**«Товар лежит в том же блоке (другая ячейка), но при «Товар
не найден» создаётся новое задание»** — фикс 1.0.1: `bf_prefix`
берётся из адреса ячейки, а не из первых символов ШК. Обновите
`utils/tasks/pick.py`.

**«Сканер на Android открывается на весь экран, не видно
задания»** — в 1.0.1+ для телефонного режима сканер встроен в
низ экрана задания/сессии. Полноэкранный сканер — только на
экранах логина.

**«Сканер на ТСД не срабатывает»** — убедитесь, что в
`MainActivity.dispatchKeyEvent` включён `acceptScans`, и что
`PdaScanHook` нашёл `MainActivity` через `ContextWrapper`. В
логе — `adb logcat -s WMS_SCAN`. Если скан не доходит —
проверьте настройки сканера (Keyboard / HID, не Broadcast).

**«Drawer на Android дёргается»** — анимация 120 мс, ширина
240 dp. Если всё ещё дёргается — соберите release APK.

**«Настройки сканера на маленьком экране обрезаются»** —
страница прокручивается, карточки не режутся.

**«Не появилась админ-страница плагина»** — в 1.0.1+
`wms.py::_register_mgmt_page` **сразу** добавляет страницу в
сайдбар (если роль подходит), а `_refresh_pages_from_server`
подтягивает её с `/mgmt/pages` в удалённом режиме. Проверьте
логи: `[wms] mgmt-страница plugin:<name>:<key> не добавлена
в сайдбар: роль <role> не в (...)`.

**«Слишком большой диапазон (N ячеек)»** — в 1.1.0 сервер
проверяет размер диапазона. Лимит 2 000 000 ячеек за одну
операцию. Если у вас реально нужно больше — разбейте на
несколько диапазонов (например, по этажам).

**«TLS включил, но клиенты не подключаются»** — после
включения TLS в «Настройках → Безопасность» **перезапустите
сервер вручную** (остановить в окне статуса → запустить
заново). Затем **все клиенты должны заново отсканировать QR**
со страницы «Задания» — в нём теперь `#fp=...`.

**«Хочу отключить TLS для старого склада»** — «Настройки →
Безопасность» → снять чекбокс → перезапустить сервер. Клиенты
на HTTP продолжат работать; клиенты, у которых сохранён HTTPS в
`config.json`/`SharedPreferences`, нужно переключить на HTTP
вручную (или заново отсканировать QR без `#fp=`).

## 26. Глоссарий

- **WMS** — Warehouse Management System.
- **View** — дерево компонентов (JSON), которое рендерит клиент.
- **Mgmt-view** — то же для ПК-клиента управления.
- **ШК** — штрихкод.
- **Адрес** — «БФ-РР-СС-Я».
- **Тара** — физический контейнер.
- **Грузоместо** — тара или партия товара, которую принимают.
- **Резерв** — временно удерживаемый товар в ячейке.
- **Batch** — группа заданий по разным блокам.
- **Частичное** — задание/грузоместо, принятое не полностью.
- **Точка сброса** — место для закрытых тар.
- **Platform** — `pc` / `android` / `any`.
- **Сессия** — долгоживущий процесс (например, приёмка).
- **Pending** — ожидание подтверждения сканом.
- **Плагин** — расширение в `plugins/` (папка или legacy `.py`).
- **TaskHandler**, **SessionHandler** — обработчики.
- **Safe mode** — запуск без плагинов.
- **ПК-клиент** — окно управления складом.
- **ПК-терминал** — тонкий view-клиент на ПК.
- **ТСД** — Android-терминал.
- **Сервер + клиент** — оба процесса на одном ПК.
- **Только сервер** — headless, без клиента.
- **Удалённый клиент** — клиент на другом ПК.
- **Окно статуса** — метрики сервера.
- **Руководитель** — `owner` / `admin` / `operator`.
- **Владелец (owner)** — руководитель, созданный вместе со
  складом.
- **Сессия приёмки** — долгоживущий процесс на ПК-терминале,
  выполняющий приёмку.
- **HID-сканер** — сканер, эмулирующий клавиатуру (как на ТСД).
- **Embedded-сканер** — встроенное в окно превью камеры (для
  телефонного режима Android).
- **ui_config** — конфиг темы, экранов, языков, меню, ролей;
  отдаётся сервером через `/ui_config`, кэшируется клиентами.
- **Реестр ролей** — `utils/roles.py`, единый список встроенных
  и плагинных ролей.
- **TLS/HTTPS** — шифрование канала между сервером и клиентами.
- **Сертификат** — самоподписанный X.509, генерируется на склад
  при включении TLS (`warehouses/<name>/tls/cert.pem`).
- **Fingerprint** — `base64url(sha256(der))` сертификата;
  передаётся в QR (`WMS://ip:port#fp=...`).
- **Pinning** — клиент доверяет только одному сохранённому
  сертификату (не системным CA).
- **TOFU** (Trust On First Use) — при первом скане QR клиент
  сверяет сертификат с fingerprint и запоминает PEM.
- **PBKDF2-SHA256** — алгоритм хеширования паролей (600k
  итераций, соль 16 байт). Используется в 1.1.0+.
- **Opaque-токен** — случайный токен сессии, не содержащий
  логин/пароль; хранится в `auth_sessions` как `sha256(token)`.
- **Rate-limit** — ограничение попыток входа (10 за 5 минут
  на пару IP+логин → блок на 15 минут).
- **`auth_sessions`** — таблица активных сессий: `token_hash`,
  `login`, `kind` (manager/employee), `role`, `created_at`,
  `expires_at`, `last_seen_at`, `ip`.
- **`tls_certs`** — кэш сохранённых сертификатов в
  `client_desktop/config.json` и `SharedPreferences "wms_certs"`
  на Android.
